# Implementation Log: Task 1

**Summary:** Dropped the createdVia eligibility gate from the shared job-patch helper updateJobFromNames. Per design C1, renamed the private NOT_FOUND_MESSAGE to an exported constant JOB_NOT_FOUND_MESSAGE = "Job not found or not owned by this token's user." (no MCP-eligibility clause), and removed `createdVia: { not: null }` from both the pre-check findFirst where and the transaction update where, so each is now exactly { id: jobId, userId }. Result: update_job and the add_job upsert path can patch any job the caller owns, regardless of how it was created. The P2025 mapping and the "Job {id} updated." message text are unchanged; addJob.ts was not touched and inherits the change.
