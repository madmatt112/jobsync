## Decisions taken in this document

- D1 — Cover-letter tool split: options were one task for shape, handler and route, or a handler task then a registration task; chosen two tasks so the handler lands unit-tested before the router exposes it.
- D2 — When the generated eval tool list is refreshed: options were in every task that changes a description or shape, or once after the last such change; chosen once in the docs task, because the file is generated, no suite reads it, and one regeneration cannot miss a later change.
- D3 — The wiki overview paragraph that says agents edit only MCP-created jobs: options were leave it, since the design's docs component does not list it, or rewrite it with the guarantee paragraph; chosen rewrite, because requirement 3 criterion 4 says the wiki states MCP writes reach every owned job and that paragraph says the opposite.
- D4 — Where the jobscout PR-body paragraph goes: options were a repository file, or the docs task's implementation log for whoever opens the PR; chosen the log, because no repository file carries a PR body.
- D5 — How the end-to-end resume resolves for the shared e2e user: options were relying on it being the only resume, linking it to the job, or setting it as default in the Profile UI; chosen default, because other specs leave resumes on that user and the job form path is not exercised elsewhere.
- D6 — Route coverage for the new tool: options were a new route-level unit suite or the end-to-end test; chosen end-to-end, because no route-level unit suite exists and the router block copies an existing gate.
